Final Review Checklist

  • Explain every answer aloud in 60–120 seconds.
  • State correctness guarantees before performance claims.
  • Connect HashMap, equality, immutability, and concurrency.
  • Explain retry safety, idempotency, and unknown outcomes.
  • Know Java 8–17 changes and a safe upgrade plan.
  • Use exact money representations and explicit currency rules.
  • Describe production diagnosis with metrics, profiles, and rollback.
  • Give trade-offs instead of declaring one tool universally best.

15 Rapid-Fire Questions

10 Common Interview Mistakes

  1. Giving definitions without a production example.
  2. Ignoring correctness while discussing performance.
  3. Claiming ConcurrentHashMap makes compound workflows atomic.
  4. Using Big-O without considering memory and cache locality.
  5. Saying Java passes objects by reference.
  6. Calling records or final fields deeply immutable.
  7. Suggesting retries without idempotency.
  8. Recommending parallel streams without profiling.
  9. Leaking infrastructure exceptions or sensitive data.
  10. Proposing a rewrite before tests and migration controls.

What to Study Next

  • Java concurrency: Java Memory Model, volatile, locks, atomics, executors, CompletableFuture.
  • JVM: heap, GC, JFR, safepoints, profiling, memory leaks.
  • Spring Boot, REST API design, resilience, security, and observability.
  • SQL transactions, isolation, locking, indexes, and Oracle performance.
  • Kafka delivery semantics, partitioning, consumer recovery, and outbox patterns.
  • System design for low-latency, high-throughput financial services.
  • Timed coding: arrays, maps, graphs, matrices, and clean explanation.
